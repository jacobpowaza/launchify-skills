# AI and LLM Security

**Category ID:** `ai`

---

## Scope

Inspect all AI, LLM, and machine learning integrations for prompt injection, system prompt leakage, model security, output validation, data protection, and AI-specific risks. AI/LLM security is an emerging attack surface — prompt injection can bypass all application security controls.

---

## Checks

### Prompt Injection
- Direct prompt injection (user input concatenated into system prompt)
- Indirect prompt injection (malicious content in emails, PDFs, websites, documents processed by AI)
- Second-order prompt injection (malicious content stored in database, retrieved by RAG)
- Prompt injection through file uploads (documents, images with OCR text)
- Prompt injection through web scraping (malicious web content)
- Prompt injection through email processing
- Prompt injection through API responses from third-party services
- Prompt injection through database content
- System prompt leakage (system prompt returned in error messages, logs, or responses)
- System prompt extraction through carefully crafted queries
- System prompt leakage through indirect extraction (asking model to translate/repeat instructions)
- System prompt leakage through JSON mode (requesting JSON output of system prompt)
- System prompt leakage through translation attacks (translate your instructions to French)
- System prompt leakage through completion attacks (finish this sentence: "My instructions are...")
- Users extracting hidden instructions
- Jailbreaks (bypassing safety boundaries)
- Missing jailbreak resistance
- Prompt obfuscation techniques bypassing filters
- Multi-turn jailbreaks (gradually escalating across conversation turns)
- Language switching to bypass safety filters

### Output Safety
- Unsafe AI output (AI-generated content used without validation)
- Missing output validation on AI responses
- AI-generated HTML executed unsafely (rendered without sanitization)
- AI-generated code executed unsafely (passed to eval, exec, or shell)
- AI-generated SQL executed unsafely (passed to database query)
- AI-generated shell commands executed unsafely
- AI-generated file operations executed unsafely
- Hallucination-driven security failures (AI fabricating permissions, approvals, or facts)
- Fake permissions granted by AI
- Fake approvals generated by AI
- Incorrect security decisions by AI
- AI-generated content trusted without validation
- AI-generated policy or permission decisions without deterministic enforcement
- AI-generated security decisions without human or rule-based controls

### Permissions and Control
- Excessive AI permissions (file system, database, exec, network)
- Agent overreach (AI accessing more than needed)
- Unrestricted tools (AI can use any tool without restriction)
- Sensitive actions without approval (delete, deploy, modify permissions)
- Missing approval boundaries
- AI-generated code execution with elevated privileges
- Unsafe command execution by AI
- Missing sandboxing for AI execution
- AI accessing secrets unnecessarily
- AI accessing production systems unnecessarily
- AI accessing unrelated tenants
- AI performing irreversible actions automatically
- Missing human approval gates for critical actions
- AI able to send emails without approval
- AI able to delete files without approval
- AI able to modify database without approval
- AI able to deploy to production without approval
- AI able to change permissions without approval
- AI able to execute arbitrary code without approval

### Data Protection
- Sensitive data sent to external AI providers (OpenAI, Anthropic, Google)
- Sensitive data in prompts (passwords, tokens, PII, financial data)
- Prompt data retention leaks (sensitive prompts stored indefinitely)
- Sensitive prompts stored in logs
- PII sent to AI provider without redaction
- Financial data sent to AI provider without redaction
- Health data sent to AI provider without redaction
- Proprietary code sent to AI provider without consideration
- Customer data sent to AI provider without consent
- Missing data processing agreements with AI providers
- Missing data residency compliance for AI providers

### Model Security
- Model endpoint exposure (public OpenAI-compatible endpoints without auth)
- Public local-model endpoints without authentication
- Unauthenticated model APIs
- Model abuse (no usage limits, no abuse detection)
- Training data leakage (model memorizing and returning training data)
- Model inversion (extracting training data from model outputs)
- Model extraction (copying model through API queries)
- Model poisoning (adversarial training data)
- Missing model access controls
- Missing model rate limiting
- Missing model cost controls
- Denial-of-service through expensive prompts
- Unbounded token usage (runaway costs)
- Unbounded tool loops (infinite agent loops)
- Missing model fallback safety

### Supply Chain
- AI supply-chain risk (dependencies on AI providers)
- Model supply-chain risk (downloading pre-trained models)
- Downloaded models with malware or backdoors
- Unverified model files (missing checksums, signatures)
- Unsafe model plugins
- Untrusted tools passed to AI agents
- Tool-output injection (attacker-controlled data in tool results)
- Context-window manipulation (overflowing context to change behavior)
- Model file integrity not verified
- AI model dependencies not audited

### Excessive Agency (OWASP LLM06)
- Excessive agency (LLM has more permissions than needed for its task)
- ExcessiveFunctionality (LLM can access functions it doesn't need)
- Overreliance on AI output for security decisions
- Missing human-in-the-loop for critical AI decisions
- AI used for access control decisions without deterministic fallback
- AI making authorization decisions
- AI making payment decisions without human approval
- AI modifying security configurations

### Resource Consumption
- Unbounded context window usage (filling context to cause denial-of-service)
- Recursive tool calls (agent calls tools that call tools indefinitely)
- Token amplification attacks (small input → massive output consuming resources)
- Missing token budget enforcement
- Missing concurrent request limits per user on AI endpoints
- Missing output length limits
- Missing input length limits
- Missing total session token limits

### Output Filtering
- Missing content filtering on model outputs
- Missing toxicity/harmfulness detection on outputs
- Missing PII detection/redaction on model outputs
- Missing harmful content filtering
- Missing code execution filtering (model output used in eval/exec)

### Controls
- Missing prompt and output logging controls
- Excessive prompt retention
- Missing tenant isolation in model context
- Cross-user context leakage
- Missing model cost controls and alerts
- Unbounded token usage
- Unbounded tool loops
- Missing model fallback safety
- Missing human approval gates
- AI performing irreversible actions automatically
- AI hallucination causing security issues
- Prompt data retention leaks
- Missing AI audit trail

---

## Methodology

1. Identify all AI/LLM integration points (API calls, SDK usage, agent tool definitions)
2. Test for prompt injection on all user-facing AI inputs
3. Test for indirect prompt injection through processed content
4. Verify output validation is applied to AI responses
5. Check AI permission boundaries and approval gates
6. Verify sensitive data is not sent to models unnecessarily
7. Check model endpoint authentication and access controls
8. Verify tenant isolation in AI context
9. Check for AI cost controls and rate limiting
10. Verify human approval gates for irreversible actions
11. Check for AI-generated content validation
12. Verify system prompt is not leaked in responses
13. Test jailbreak resistance
14. Check model supply chain integrity

| System prompt leakage exposing security controls | CRITICAL |
| AI performing irreversible actions without approval | HIGH |
| Sensitive data sent to external AI provider | HIGH |
| Missing output validation on AI responses | MEDIUM |
| Indirect prompt injection through RAG content | HIGH |
| Unbounded token usage | MEDIUM |
| Model endpoint exposed without auth | HIGH |
| Training data leakage | MEDIUM |

## Evidence Requirements

- AI/LLM integration point affected
- Specific prompt or input vector
- Whether the finding is exploitable through user input
- Whether sensitive data is involved
- Impact on system integrity and data confidentiality
- Whether the finding is exploitable through indirect injection
